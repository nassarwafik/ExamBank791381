## Teacher (real preview account, no production changes)

- [ ] Sign in as a teacher on the preview, create a **test** exam, import the 21A.2 JSON through the exam builder's actual import path, and save.
- [ ] Confirm all nine sections and all nine top-level question positions and the two scored composite parts; check their mathematical graphs render as authored, not approximated or regenerated by AI. Ensure total available marks = 38.
- [ ] Check the nine authored scenario families: A quadratic roots/extremum, B rational poles/asymptotes, C sine with π ticks, D piecewise open/closed endpoints, E curve intersections, F derivative/tangent/normal, G shaded area and interval, H Arabic RTL around LTR math, I composite sharing a circle/graph context.
- [ ] In the question editor, add/edit/remove a curve or selectable point; save, reload, and verify persistence. Undo test edits before using the canonical acceptance exam.
- [ ] Preview as teacher; verify *teacher-only* roles, answers and authored on-curve claims do not appear in any student preview or network/API JSON.
- [ ] Run the actual readiness/governance checks; publish the test exam, assign it to synthetic test student accounts, and confirm the assignment snapshot remains immutable if a teacher changes a local draft.
- [ ] Export/reimport the test exam; validate stable identities, formulas, grades, and graph IDs. Verify the canonical fixture was not silently rewritten.

## Student (synthetic accounts)

- [ ] Before the assignment opens, a student cannot retrieve protected exam content from the UI or delivery API.
- [ ] Start the assignment through the actual Student Portal. Verify every graph (including composite context) and its nonvisual values table; check mathematics in Arabic RTL without reversing formula source.
- [ ] Use only a keyboard to select and deselect semantic targets; then repeat using touch on a narrow viewport. Check zoom, pan and trace do not change semantic answer identities.
- [ ] Verify portrait widths 320 / 360 / 600 px and desktop widths 800 / 1024 / 1280 px; no clipped interaction controls, hidden marks, misplaced endpoints or invisible graph axes. Check Chrome print preview/PDF without printing real student data.
- [ ] Enter partial answers, wait for a confirmed draft save, reload the page, and verify that **the same graph IDs and target selections** are restored.
- [ ] Submit four controlled answer profiles from the certification reference: PERFECT, PARTIAL, BLANK and an invalid/forged response; use separate synthetic student accounts.
- [ ] For PERFECT / PARTIAL / BLANK, verify authoritative **38 / 30 / 0 marks** using the official answer ledgers in `api/tests/certification-21a2/cert-21a2-platform-lifecycle.test.js`. These figures assume *precisely* the tested answer sets; do not apply them to different choices.
- [ ] For forged graph IDs, unknown targets, duplicates, client-supplied marks, and more selections than allowed, verify safe rejection/zero and never accept a forged grade as official.
- [ ] Submit the same attempt twice or refresh after submit; confirm the server returns the same final result without double submission.

## Teacher review and audit

- [ ] Open each attempt in the real teacher review screen. Verify submitted semantic targets, public math context, and official keys are displayed only to authorized teacher roles.
- [ ] Verify the original marking ledger against the displayed score and manual-review indications; save a review note on the test assignment and reload it.
- [ ] Export an audit record/screenshots with synthetic identities only; verify no answer keys/roles leak through student preview, print or student API calls.

## Negative and regression gates

- [ ] Reject arbitrary HTML/script attributes, unknown keys, oversized mathematical expressions, impossible numeric ranges, and wrong graph version on both editor import and API finalization. No client crash or infinite CPU loop.
- [ ] Existing non-graph question types still create, publish, answer and grade as before.
- [ ] Low-network/suspend/reload behavior does not lose previously confirmed draft answers.
- [ ] Record accessibility problems (focus order, keyboard alternative, contrast, graph values table) and any mobile layout issues as blockers, not cosmetic success.
