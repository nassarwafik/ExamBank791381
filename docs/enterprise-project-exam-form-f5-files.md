# Phase F5 (files) — Project exam form: the student's files, server side

> **Owner decision, 2026-11-15 — files are not uploaded to the site.** Taken after this phase merged. The screens of this
> phase (F5-UI: the student's upload control, the teacher's switch, the download link) are **not built**. What is described
> below stays in the code, switched off for every class: no screen sends `fileAnswers`, so no student can attach a file
> and file questions stay deferred and never block a submit. The student's page now tells the student to hand the file to
> the teacher. A teacher's direct API call could still switch file answers on for a class (and its required file
> questions would then block the submit with no input on the page); whether this server side is refused outright or
> removed is the owner's open decision.

## Problem

Both bundled forms end by asking for the project itself: 794589 asks «أرفق ملف Packet Tracer النهائي» (`.pkt`) and «أرفق كتاب
المشروع النهائي» (`.docx` / `.pdf`); 883589 asks for the book. Since F2 those questions are shown and take no answer, and never
block a submit. The owner decided in F1 that files come in F5 (owner decision 3) and left the choice of the next phase to
this window on 2026-11-14.

This phase is the **server side**, as F2, F3 and F4 were: where a file is stored, what it must look like, who may read it,
and what it means for a submit. The student's upload control, the teacher's switch and the download link in the review are
the next phase (F5-UI). Until then no screen can switch file answers on, so nothing changes for any user.

F5 has two more parts that are **not** here: the PDF export and the 899373 question bank.

## Scope

| In this phase | Not in this phase |
|---|---|
| A per-class switch: file answers on | The teacher's control that sends the switch — F5-UI |
| Attach (or replace) the file of a file question, remove it (student) | The student's upload control — F5-UI |
| Download one file: the student who owns it; the teacher of the class | The download link in the teacher's review — F5-UI |
| File questions count for progress and submit where files are on | PDF export; the 899373 form |
| | Deleting a class's or a leaving student's files (no deletion without the owner's plan) |

## Decisions taken in this phase

The model is F4's (student images), changed only where a file differs from an image.

| Question | Decision | Why |
|---|---|---|
| Do file questions become answerable for every class at once? | **No.** Off until the teacher switches them on (`fileAnswers: true` on `examForm.open`), at the first open or later; never off again (`409 FILES_FROZEN`). Independent of the image switch. | Same reasons as F4: a class already filling the form was told file questions do not block; a class that attached files cannot lose the input. |
| How many files per question? | **One.** Attaching another replaces it (the new reference in one CAS round, then the old bytes are removed). | «الملف النهائي» is one file; a list would need a rule for which one counts. |
| Can a file be sanitized like an image? | **No.** There is no re-encoder for a Packet Tracer file or a Word document. So the platform **never interprets, renders or serves a file inline**: opaque bytes in, the same bytes out, as a download only. | Re-encoding is what makes an image safe to show. Without it, the safe handling is to never show. |
| What is checked, then? | The extension is one the question accepts; the bytes look like that kind (below); the name is reduced to a label; the size is bounded. | Keeps the input to what the form asks for. **It is not a malware scan** (see Known limits). |
| How large? | **10 MB** per file (`413 TOO_LARGE`). | A real 794589 work-in-progress book is 2.3 MB and its `.pkt` 0.2 MB. A final book with many screenshots may be larger: the student can export it to PDF. Open for the owner. |
| Does attaching a file advance `revision`? | **No**, as for an image: it overwrites no other answer. | A text save is never refused because a file was attached meanwhile. |
| Where is the file referenced? | Inside the answer of its question: `answers[questionId].file = { id, name, ext, bytes, addedAt }`. | One answer per question stays the model; the teacher's review read (F3) carries the reference with no change. |

## Storage

| Document | Blob | Shape |
|---|---|---|
| Class form (F2) | `platform/project-exam-forms/<code>/classes/<classId>.json` | gains `fileAnswers: true`, `fileAnswersAt`, `fileAnswersBy` — only once switched on (absent otherwise) |
| Student answers (F2) | `…/answers/<classId>/<studentId>.json` | the answer of a file question is `{ file: { id, name, ext, bytes, addedAt } }` |
| File (new) | `platform/project-exam-forms/<code>/files/<classId>/<studentId>/<fileId>.bin` | the uploaded bytes, unchanged; content type `application/octet-stream`; `fileId` is 24 hex characters generated by the server |

The stored name is always `<id>.bin`: neither the uploaded name nor its extension reaches the blob name. No existing
document is moved, rewritten or deleted.

## What an upload must look like

In this order, each refusal before the next step and before anything is stored:

1. **Name** (`400 FILE_NAME` / `FILE_TYPE`). Only the last path segment is kept; control characters and the bidirectional
   marks, overrides and isolates are dropped (a name must not display as another extension); at most 120 characters. The
   extension — the text after the last dot, lower-cased — must be one the question's `accept` lists. `book.docx.exe` and
   `book.docm` are refused.
2. **Size** (`413 TOO_LARGE`). The base64 text is bounded before it is decoded, and the decoded bytes again.
3. **Content** (`400 FILE_CONTENT` / `FILE_MACROS`):

| Extension | The bytes must | Refused examples |
|---|---|---|
| `.pdf` | start with `%PDF-` | text, a Word document, an image |
| `.docx` | be a ZIP holding `[Content_Types].xml` and `word/document.xml`, with **no** `vbaProject.bin` | any other ZIP, a PDF, a document with a macro project |
| `.pkt` | **not** start as an executable (PE, ELF, Mach-O, Java class), an archive (ZIP, RAR, 7z, gzip), a PDF, RTF, a script (`#!`) or markup (`<!doctype`, `<html`, `<?xml`, `<svg`, `<script` …) | a renamed `.exe`, `.zip`, `.html`, `.svg`, shell script |

A Packet Tracer file has no published signature (current versions are an encrypted stream), so it cannot be recognised
positively; the rule lists what it must not be. A real 794589 `.pkt` and book were checked against these rules locally and
are accepted; they are not in the repository (a student's work).

## API

**Teacher** — `api/src/functions/project-tracker.js`, behind its existing dispatch (`GET` → `projects.tracker.view`, every
action → `projects.tracker.manage`; the teacher's own class, enrolled in the project; an archived class refuses every
action). No new route, no new capability.

| Request | Result |
|---|---|
| `action=examForm.open` `{ fileAnswers: true }` | switches the class's file answers on, at the first open or later. `changed: true` and an audit record `project.exam_form.open` with `fileAnswers: true` when the switch moved. `false` on a class that has it on is `409 FILES_FROZEN`; a non-boolean is `400 BAD_FILE_ANSWERS`. |
| `GET resource=exam-form` | `examForm.fileAnswers: true` once on (absent while off) |
| `GET resource=exam-form-file&studentId=&fileId=` | the file, as a download. The student must be a member of the class and the file must be referenced by that student's answers; anything else is `404`. |
| `GET resource=exam-form-student` (F3) | unchanged; the answer of a file question carries its `file` reference (name, size) |

**Student** — `api/src/functions/student-project-exam-form.js`. The student and the class come only from the session.

| Request | Result |
|---|---|
| `POST { projectCode, action: "addFile", questionId, fileName, dataBase64 }` | checks and stores the file, references it from the answer (replacing the question's earlier file); the form body plus `file: { id, name, ext, bytes }` |
| `POST { projectCode, action: "removeFile", questionId, fileId }` | removes the reference and the bytes; `changed: false` when that file is not there (a repeat is harmless) |
| `GET ?projectCode=&file=<fileId>` | the student's **own** file, as a download (`404` otherwise). Readable in an archived class too (its record). |
| `GET ?projectCode=` | `deferredKinds` follows the two switches: `["image","file"]`, `["file"]`, `["image"]` or `[]`; `progress` counts file questions accordingly |

Refusals, each writing nothing and storing no blob: files off for the class `400 KIND_NOT_AVAILABLE`; a question that is not
in the class's form (unknown or hidden) `400 UNKNOWN_QUESTION`; a question that is not a file question `400 NO_FILE_HERE`;
closed `409 FORM_CLOSED`; submitted `409 FORM_SUBMITTED`; approved `409 FORM_APPROVED`; archived class `403`; form never
opened `404 FORM_NOT_OPENED`; a draft save that names a file question `400 FILE_VIA_UPLOAD`. A returned form takes a file
again, like its other answers.

**Both downloads** answer with `Content-Type: application/octet-stream` (a PDF too — never `application/pdf`),
`Content-Disposition: attachment` with an ASCII fallback name and the UTF-8 name (RFC 5987), `X-Content-Type-Options: nosniff`
and `Cache-Control: private, no-store`.

## Answer rules with files on

| Question | Counts as answered when |
|---|---|
| `file` | it holds its file |
| every other kind | as in F2 / F4 |

A required file question therefore blocks a submit (`400 FORM_INCOMPLETE`, listed in `missing`) until its file is attached.
With files off every rule is the earlier one: file questions are deferred, never counted, never blocking.

## Safety

- **The server decides.** A reference is written only by the server, with an id it generated for a blob it stored. A draft
  save that names a file question is refused outright, and a `file` field sent on any other question is dropped (a draft
  rebuilds each answer from the fields its question allows).
- **Protected content never bypasses the API.** A file is not a static asset and has no public URL. It is served only when
  the answers document of that student references it: to the student (the session's own identity) and to the teacher of
  the class (capability, tenancy, class enrolment, membership). The id alone is never enough: the blob name is built from
  the class and the student too, and an existing blob that is no longer referenced is not served.
- **Never rendered.** No route serves a file inline or with a type a browser may render or guess; the platform never opens
  or parses one beyond the signature checks above.
- **Fail closed.** Order of the attach: name → size → content → store the blob → reference it in one CAS round. When the
  round refuses (form closed or submitted meanwhile, storage conflict) the blob just written is removed, and the answers
  are untouched. A replaced file's bytes are removed only after the new reference is stored.
- **Grading safety.** Nothing here produces a mark. A file question that was never switched on is «not asked», not a
  missing answer; a failed upload is an error the student sees, never an empty answer stored.
- **Identity.** A body `studentId` / `classId` is never read on the student route.
- **No new infrastructure.** Files are blobs in the existing container. No new dependency.
- **Nothing is deleted or migrated.** A class reset, a closed form and a student who leaves the class keep their files; a
  former member's files are no longer served through the class (the same policy as F3 and F4).

## Known limits

- **No malware scan.** The checks keep an upload to the kinds the form asks for; they do not prove a file is harmless. A
  `.pkt`, a Word document or a PDF a teacher downloads is a student's file, to be opened like one received by e-mail. The
  platform itself never opens it. Adding a scanner is new infrastructure and the owner's decision.
- **No user can reach any of this until F5-UI**: no screen sends `fileAnswers`, attaches a file or links to one. F5-UI must
  ship the student's input together with the switch (a class switched on through the API alone would show required
  questions with no input; nothing in the product can do that today).
- **The hosting's request-size limit was not verified.** A 10 MB file is about 13.4 MB as base64 inside a JSON body. The
  tests run the handlers in process; whether the deployed host accepts a body of that size must be checked on the PR
  preview or in production before F5-UI offers the full 10 MB (F4 uploads at most 6 MB the same way).
- A file is held in memory by the Functions host while it is checked and stored, and again when it is downloaded.
- There is no quota beyond one file of at most 10 MB per file question (two questions in 794589, one in 883589).
- The teacher's review page (F3-UI) still says a file question is checked from the student's book; showing the download
  link is F5-UI.
