# Phase 19B — Parametric Questions Engine (`parametricNumeric@1`)

Baseline `b8aa6ce12a48f7d0bb5fb69264521249cffb6733` (post-merge of Phase 19A, PR #255). Branch
`feature/19b-parametric-questions-engine`. One new versioned question family, `parametricNumeric@1`
(«سؤال رقمي بمعطيات متغيرة»), built on a reusable deterministic parametric engine. A teacher authors ONE template; every
student and every attempt receives its own deterministic instance, regenerated by the server for delivery, grading and review.

**This is not arbitrary code execution.** There is no `eval`, no `Function`, no dynamic import, no JavaScript / Python
parsing, no shell and no external execution anywhere in the engine. Expressions are parsed by a closed recursive-descent
grammar into an AST and evaluated by a bounded interpreter that knows six functions and five operators.

## 1. Architecture

| Layer | File | Responsibility |
|---|---|---|
| Engine (reusable, family-agnostic) | `src/parametricEngine.ts` | expression language, constraints, integer variables, `{{id}}` template, generation identity, versioned generator |
| Question family | `src/parametricNumericQuestion.ts` | public / private contract, validator, per-attempt student projection, ingest binding, scorer, review instance, teacher sample |
| Registry | catalog row, defaults, `registerTypeValidator`, lazy editor / renderer, `registerGrader` | the Phase 16A seams — no central `if` chain |
| Server | `assignment-grading.js`, `question-type-graders.js`, `student-exam-sanitize.js`, `draft-answers.js`, `student-assignment.js`, `student-submission.js`, `assignment-results.js`, `assignment-review.js` | identity threading, per-attempt delivery, binding, grading, review |
| Shared build | `scripts/build-shared-finalization.mjs` | both modules compiled to `api/src/lib/shared-finalization/*` (drift-guarded) |
| UI (lazy) | `questionTypes/student/ParametricNumericResponse.tsx`, `questionTypes/editors/ParametricNumericEditor.tsx`, `parametric/ParametricReviewView.tsx` | student input, teacher editor + sample preview, teacher review |
| AI | `src/aiQuestionDraft.ts` (intent `parametricNumeric`) | AI proposes; the canonical validators decide |

The engine never names a presentation type; the subnet / maths / physics knowledge lives only in authored content.

## 2. Deterministic seed contract

The **official** instance of a question in an attempt is fully determined by

```
generation identity = { assignmentId, studentId, attemptNumber, questionKey }   +   generatorVersion
seed text           = JSON.stringify(["smartassess.parametric", generatorVersion, "official",
                                      assignmentId, studentId, attemptNumber, questionKey])
```

* `assignmentId` — the assignment storage id (the published exam snapshot is frozen per assignment, so it is also the exam
  version identity).
* `studentId` — the authenticated student (delivery / submission) or the submission path (teacher end, review).
* `attemptNumber` — the number the server stamped on the attempt: the active attempt's number, otherwise completed attempts + 1
  (exactly what a legacy untimed lazy save / submit stamps). It does not change on refresh, autosave, pause / resume, extension,
  submit, timeout, integrity exit or teacher end. A reopened / retried attempt is a new number ⇒ a new instance.
* `questionKey` — the section-scoped grading key (`sectionQuestionId`: explicit `examQuestionId` / `id`, else `section::qN`, else
  the legacy fallback), the SAME key the grader and the answers map use — delivery and grading can never disagree.

Rules: the client never sends, chooses or sees the seed; nothing in a request body can influence the identity
(`parametricGenerationContext` is built only from server state). The seed contains no grading secret and the private key is never
a PRNG input (generation reads only the public config). The seed text is a JSON array, so no id can forge a delimiter. The
teacher-review audit shows `seedDigest` (hex of the 128-bit hash), never anything private. Preview samples use a separate
namespace (`"preview"`, question key, sample number) that can never equal an official seed.

## 3. Generator versioning

`generatorVersion: 1` = cyrb128(seed text) → four 32-bit words → sfc32; 12 warm-up outputs; one 53-bit float per draw
(`((u1>>>5)·2^26 + (u2>>>6)) / 2^53`); per candidate, variables are drawn in declared order with
`value = min + floor(float × count) × step`; constraints are checked in declared order; at most **100** candidates; then an
explicit `GEN_CONSTRAINTS_UNSATISFIED`. Only integer IEEE operations and `Math.imul` are used, so Node and every browser
produce identical values (pinned by tests computed with an independent reference implementation).

A future algorithm is registered as a **new** generator version; version 1 never changes, so historical attempts replay
exactly. An unsupported `generatorVersion` is refused by the validator, the projection, the grader and the review
(fail closed) — never silently generated with another version.

## 4. Public / private boundary

| Where | Content |
|---|---|
| `question.parametric` (public, authoring only) | `{ v: 1, generatorVersion: 1, variables: [{ id, kind: "int", min, max, step }], constraints: [..], response: { unit: "none" } \| { unit: "label", label } \| { unit: "input" } }` |
| `question.text` | the stem template with `{{id}}` placeholders |
| `question.answer` (private) | `{ expression, mode: "tolerance", tolerance, unit? }` or `{ expression, mode: "range", below, above, unit? }` — `unit` exactly when `response.unit` is `"input"` |
| student payload | `text` = the stem rendered with this attempt's values; `parametric` = `{ v: 1, status: "ready", generatorVersion, values, response }` (values of the variables the stem shows) or `{ v: 1, status: "unavailable" }` |
| student answer | the existing `{ kind: "numeric", value, unit? }` — bounded strings only |

The sanitizer REPLACES `parametric` with the strict projection (the authored config, constraints and template never reach a
student) and blanks `answer` as for every type; `textHtml` is dropped for parametric nodes. No identity (live challenge,
practice, a structured exam's stray flat list) or an invalid public contract ⇒ the explicit `unavailable` projection. A smuggled
field inside the public config makes it invalid ⇒ unavailable. The computed correct value is never persisted as authority and
never sent to a student.

## 5. Safe expression grammar

```
expression := additive
additive   := multiplicative (("+" | "-") multiplicative)*
multiplicative := unary (("*" | "/" | "%") unary)*
unary      := "-" unary | power
power      := primary ("^" unary)?                      (right associative; -2^2 = -4)
primary    := number | variable | function "(" args ")" | "(" additive ")"
number     := digits ("." digits)?                      (≤ 15 integer digits; no exponent notation, no hex)
function   := abs | floor | ceil (1 arg) | round (1–2 args) | min | max (2–10 args)
constraint := additive ("<" | "<=" | ">" | ">=" | "==" | "!=") additive        (exactly one comparison)
```

Limits: expression ≤ 500 characters, constraint ≤ 300, ≤ 200 tokens, AST depth ≤ 32, every intermediate value finite and
|v| ≤ 10^15, exponent an integer with |e| ≤ 64 (computed by repeated squaring), `round(x, d)` with 0 ≤ d ≤ 10 rounds half away
from zero after removing binary noise (`toPrecision(15)`), `%` is the truncated remainder. Division / remainder by zero,
`0 ^ negative`, non-finite or out-of-range values are evaluation failures. Anything else — member access (`.`), strings,
arrays, assignments, `;`, `=>`, `?:`, `&&`, `!`, unknown functions (`sqrt`, `log2`, `Math.max`, `eval`, `require`, `import`),
prototype-sensitive identifiers (`__proto__`, `constructor`, `prototype`, `toString`, …) — is a parse failure. Variable lookup
uses an own-key `Map`, never an object's prototype chain.

## 6. Variables, constraints, template

* Variables: 1–20; `id` matches `^[A-Za-z][A-Za-z0-9_]{0,31}$`, unique, not a function name or a prototype-sensitive name;
  `kind: "int"`; `min` / `max` safe integers within ±10^9 with `min ≤ max`; `step` a positive integer and `max − min` a
  multiple of `step` (so the declared range is exactly reachable). Exact keys only.
* Constraints: ≤ 20 single comparisons over declared variables. A constraint that errors (e.g. divides by zero) never holds.
  Unsatisfiable constraints fail after exactly 100 candidates — never an infinite loop, never a silently ignored constraint.
* Template: literal text plus `{{id}}` placeholders; `{{ a }}`, `{{a.b}}`, `{{{a}}}`, `${a}`, unbalanced braces, empty or
  reserved names are refused; every placeholder must name a declared variable and at least one must appear. Rendered as plain
  text (React text nodes), never HTML.
* Authoring-time sample check: the validator generates 8 preview-namespace samples; an impossible constraint set
  (`PARAM_SAMPLE_GENERATION_FAILED`) or an answer expression failing on a sample (`PARAM_SAMPLE_ANSWER_FAILED`, e.g. a division by
  zero — add a constraint such as `b != 0`) blocks finalization.

## 7. Grading

`scoreParametricNumeric` (server, through the `parametricNumeric@1` grader): validate the public config → validate the private
key → validate the stem template → validate the server identity → regenerate the official instance → evaluate the answer
expression → apply the **existing numericResponse comparison** (`scoreNumericResponse`: Arabic-Indic / English digits and
separators, inclusive epsilon-safe tolerance or range, all-or-nothing marks). `tolerance` is absolute (0 = exact); `range` accepts
`[expected − below, expected + above]`. Unit (`response.unit: "input"`): NFKC, whitespace removed, **case-insensitive**, exact
match — no equivalences and no conversion in V1.

| Situation | Result |
|---|---|
| valid authority, correct / incorrect / empty / non-numeric / wrong-kind response | marks or ordinary 0, `manualReview: false` |
| invalid public config / key / template, unsupported generator or type version, no / malformed identity, unsatisfiable constraints, expression failing on this instance | `score 0, correct false, manualReview true` — never a manufactured academic zero |

`gradeExam(exam, answers, context)` threads `context.parametric` (+ the per-question key) to registered handlers as a 4th
argument; every other grader ignores it, so all existing grades are unchanged.

## 8. Attempt lifecycle

Every official grading call site passes `parametricGenerationContext(assignmentId, studentId, attemptNumber)`: submit,
`finalizeTimedOutAttempt`, `finalizeIntegrityExit` (strict exit and expired finalize) in `student-submission.js`, and the
teacher's `endActiveAttempt` in `assignment-results.js`. `student-assignment.js` delivers the same identity
(`deliveryGeneration`). No second attempt-state system exists: the instance is a pure function of the existing attempt
authority. Tested through the real handlers: refresh, pause → resume, draft restore, submit, a reopened attempt (#2 gets its
own instance), a legacy untimed assignment (instance identical before and after the lazy draft attempt), teacher end, and the
teacher review regenerating the identical instance. Learning practice and live challenges carry no official identity: the
question renders as unavailable there and would grade to manual review.

## 9. Teacher authoring, student UX, review

* **Editor** (lazy): variables table (id, from, to, step, insert `{{id}}` into the stem, remove), constraints list, answer
  expression (LTR), comparison mode (tolerance / range), unit policy (none / fixed label / student types the unit + the correct
  unit), the canonical issues, and a **sample preview** («عينة معاينة» — preview namespace, teacher only): values, rendered stem
  and the sample's correct answer, with «عينة جديدة». No JSON, no textarea.
* **Student** (lazy): the rendered stem (card), a labelled `inputmode="decimal"` LTR input, a unit input or a fixed unit label,
  restore and read-only through the existing pipeline; an unavailable projection renders an explicit notice and no input.
  Teacher preview shows a labelled preview sample.
* **Review**: the exact official instance from the server (`parametricInstance` in `assignment-review`), the student's answer,
  the authoritative expected value, the answer expression (teacher only) and the audit identity (generator version, attempt,
  question key, seed digest); an instance the server cannot regenerate is an explicit manual-review state.

## 10. AI authoring

Intent `parametricNumeric` joins the Phase 19A vocabulary; bilingual request signals («بأرقام مختلفة لكل طالب», «سؤال رقمي
يتغير لكل طالب», "parametric", "random integers", "different numeric version for each student") are advisory. The AI fills
`{ variables: [{ name, min, max, step }], constraints, answerExpression, mode, tolerance, below, above, unitMode, unitLabel, unit }`
in a strict schema; the normalizer maps it field by field (`name` → `id`) and `verifyAiQuestionNode` runs the structured-exam
quality gate, i.e. `validateParametricNumericQuestion`, server-side and again in the Builder dialog. Unknown functions, unsafe
expressions, impossible ranges, unknown references, malformed constraints and failing samples are refused with the canonical
issues — never repaired. A 19A-shaped draft without the new key is still accepted (no payload).

## 11. Limits and V1 exclusions

Integer variables only; no floating / categorical variables, no random distributions other than uniform-on-the-grid, no
symbolic algebra, no unit conversion or unit equivalence, no per-variable display formatting, no partial credit, not a compound
part, no IPv4 / dotted-quad values or bit operations, no logarithms or roots. Practice / live challenge do not deliver
parametric instances.

## 12. Security model

Client authority is never accepted: ingest keeps exactly `{ kind: "numeric", value, unit? }` (a forged seed, generated values,
expected result or score is dropped before storage); grading regenerates from server state only; the student projection is a
strict allow-list built from the public config; the renderer reads it through a strict reader. Prototype-sensitive keys are
refused at every level (config, key, variables, identifiers, template). Mutation-tested invariants: see the PR.

## 13. Networking readiness and future extensions

The generic language already expresses subnet arithmetic: usable hosts of a generated prefix `2 ^ (32 - p) - 2`, block size
`2 ^ (32 - p)`, host bits `32 - p` (end-to-end tested). Operations that need IPv4 semantics — rendering dotted-quad addresses,
network / broadcast addresses, masks from prefixes, `log2` / ceiling-of-log for "smallest prefix for N hosts", bitwise AND —
are deliberately **not** shoehorned into the generic language. They belong to a future, separately versioned **safe domain
function** extension (e.g. an `ipv4` profile with pure, bounded, typed functions and a dotted-quad answer kind), added
additively with its own generator / language version.
